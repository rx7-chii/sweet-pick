# SWEET PICK 本番デプロイ手順

## 現在の状態

| 項目 | 状態 |
|------|------|
| UI / 機能（MVP） | ✅ 完成 |
| データ | モック 13 商品（`lib/mock-data.ts`） |
| Supabase 接続 | ⏳ Phase 2（未接続） |
| ホスティング想定 | **Vercel** |

**今すぐデプロイ可能:** モックデータ版を Vercel に公開し、URL を共有できます。  
**本格本番:** Supabase 接続 + 商品 50 件以上が追加要件です（開発計画 DoD）。

## 方式 A：モック版を今すぐ公開（推奨・最初の一歩）

ログイン不要・DB 不要で、現在のデモと同じ内容がインターネット上で動きます。

### 1. GitHub にリポジトリを作成

`demo-implementation` フォルダを Git リポジトリにします。

```powershell
cd demo-implementation
git init
git add .
git commit -m "Prepare SWEET PICK for production deploy"
```

GitHub で新規リポジトリを作成し、push します。

```powershell
git remote add origin https://github.com/<ユーザー名>/sweet-pick.git
git branch -M main
git push -u origin main
```

### 2. Vercel にインポート

1. [https://vercel.com](https://vercel.com) にログイン
2. **Add New → Project**
3. GitHub リポジトリ `sweet-pick` を選択
4. 設定（通常はデフォルトで OK）:

| 項目 | 値 |
|------|-----|
| Framework Preset | Next.js |
| Root Directory | `./`（リポジトリルートが demo-implementation の場合） |
| Build Command | `npm run build` |
| Output Directory | （空のまま） |
| Install Command | `npm install` |

5. **Environment Variables** — モック版では **追加不要**
6. **Deploy** をクリック

### 3. デプロイ後の URL

| ページ | URL |
|--------|-----|
| アプリ本体 | `https://<プロジェクト名>.vercel.app/` |
| 宣伝ページ | `https://<プロジェクト名>.vercel.app/promo/index.html` |

## 方式 B：Supabase 連携の本番（Phase 2）

設計書どおりの本番構成です。以下が揃ってから Vercel に環境変数を設定します。

### 1. Supabase プロジェクト作成

1. [https://supabase.com](https://supabase.com) でプロジェクト作成（リージョン: 東京推奨）
2. **SQL Editor** で `docs/design/database-design.md` に基づくマイグレーションを実行
3. **Storage** で `product-images` バケットを public 作成
4. 商品データを 50 件以上シード

### 2. Vercel 環境変数

Vercel ダッシュボード → Project → Settings → Environment Variables:

| 変数名 | 説明 |
|--------|------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase プロジェクト URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY` | anon / publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key（サーバー専用・非公開） |
| `NEXT_PUBLIC_IMAGE_DIRECT_FETCH` | `true`（推奨・画像を CDN 直接取得） |

### 3. アプリ側の作業（未実装）

- API ルートを `mock-data.ts` から Supabase クエリに切替
- `@supabase/supabase-js` / `@supabase/ssr` の導入と接続テスト
- プライバシーポリシーページ（`/privacy`）

## 方式 C：Vercel CLI（ローカルから直接）

```powershell

npx vercel --prod
```

> **注意:** 社内ネットワーク等で SSL エラーが出る場合は、Vercel ダッシュボードからの Git 連携（方式 A）を使ってください。

## トラブルシューティング

### ビルドが失敗する

```powershell
cd demo-implementation
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run build
```

### 画像が表示されない

- モック版: `public/images/sweets/` がデプロイに含まれているか確認
- Supabase 版: `NEXT_PUBLIC_IMAGE_DIRECT_FETCH=true` と Storage の public 設定

### カスタムドメイン

Vercel → Project → Settings → Domains から追加可能。
